# Paths that must NEVER enter an OTA update payload.
#
# WHY THIS FILE EXISTS
# --------------------
# zohara-profile/airootfs/ is a *live ISO* overlay. Two separate pipelines take that same tree and
# copy it onto an *already-installed* user system:
#
#   1. create_update_bundle.sh  -> self-extracting zohara-update-*.sh, whose install_update.sh does
#                                  `cp -a "$DIR/airootfs/." /` with no package manager in the way.
#   2. .github/workflows/build-update.yml -> the `zohara-system` pacman package, whose package()
#                                  does `cp -a ".../airootfs/." "${pkgdir}/"`.
#
# Both used to ship the whole overlay, which meant an update would overwrite live-ISO scaffolding
# onto a real machine. Verified in the 2026.08.23 bundle, that included:
#
#   * etc/passwd  ("root:x:0:0:root:/root:/usr/bin/zsh")  -> deletes every user account
#   * etc/shadow  ("root::14871::::::")                   -> gives root an EMPTY password
#   * etc/systemd/system/getty@tty1.service.d/autologin.conf -> root autologin on tty1
#   * etc/sddm.conf.d/99-autologin.conf ("User=root")     -> graphical root autologin
#   * etc/mkinitcpio.conf.d/archiso.conf                  -> next kernel update builds an *archiso*
#                                                            initramfs; the machine stops booting
#   * etc/systemd/journald.conf.d/volatile-storage.conf   -> journal moves to tmpfs, logs lost on boot
#   * etc/systemd/system/pacman-init.service (+ its .wants link, which install_update.sh then
#     `systemctl enable --now`s) -> reinitializes the user's pacman keyring
#   * etc/hostname ("archiso")                            -> resets the hostname
#   * root/customize_airootfs.sh                          -> the build-time chroot script itself
#
# HOW THE LIST WAS DERIVED
# ------------------------
# Mechanically, not by judgement: everything below that is not in the "Zohara-authored" section is a
# path that also exists in upstream archiso's own profile, i.e. it is live-ISO scaffolding that
# Zohara inherited rather than payload Zohara ships. Regenerate the inherited set with:
#
#   comm -12 \
#     <(cd zohara-profile/airootfs && find . \( -type f -o -type l \) | sed 's|^\./||' | sort) \
#     <(cd /usr/share/archiso/configs/releng/airootfs && find . \( -type f -o -type l \) | sed 's|^\./||' | sort)
#
# (Run the second half inside the zohara-builder image, which has archiso installed.)
#
# Blank lines and lines beginning with # are ignored. Paths are relative to airootfs/.
# The ISO is unaffected by this file -- these paths are correct *there*, which is the whole point.
