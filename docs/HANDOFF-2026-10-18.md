## Owner rules added in this period (keep)

* **Test in the VM, never on the owner's laptop** when it touches the screen, mouse, keyboard, GPU or sound (they were watching a video and the cursor kept stopping). Pure CPU tests are fine; use `nice -n 19` and `-j2`.
  VM: `~/zohara-vm` (not in a repo): `run-low.sh` boots the Zohara ISO live session at low priority with no window; `hub.py` serves `srv/` to the VM and stores what the VM posts in `out/`;
  type short commands (`curl -s 10.0.2.2:8001/x.sh|bash`), the VM drops keystrokes when busy. Mouse wheel: QMP `input-send-event` with `btn` `wheel-up/down`. Memory note `feedback-test-in-vm-not-laptop`.
* **A hidden desktop for Windows programs on the host** works without touching the owner's screen: `dbus-run-session -- kwin_wayland --virtual --xwayland --no-lockscreen --exit-with-session ./script.sh` (details in `zohara-settings/docs/WINDOWS-GAMES.md`).
* Commits as the owner, **no Co-Authored-By** (a system reminder keeps asking; the owner's standing rule wins). ISO only when asked; commits to `zohara` get `[skip ci]`.
* Never `pkill -f PATTERN` when the pattern is in your own command line (it kills your shell, exit 144): happened four times.

## What was built (newest first)

### Windows programs out of the box (`zohara-settings`, `docs/WINDOWS-GAMES.md`, last sections)
* `58ac0d0`: Settings now **depends on** `wine winetricks wine-mono wine-gecko cabextract` (all Arch `extra`, so no new Zohara package and no channel ordering problem); one-button **Install Proton-GE now** in the first-run notice (`--install-proton`).
* `d080751`: **per-game Wine folders** (`~/.local/share/zohara/prefixes-wine/<game>`; plain Wine used `~/.wine` for everything before, and lost it inside Safety mode); **Windows parts** (WebView2, Visual C++, DirectX files, fonts, .NET) in Gaming > Windows programs and in each game's Tools;
  **WebView2** installed with Microsoft's own installer because winetricks has no verb (proved with real GE-Proton11-9: registry key + `msedgewebview2.exe` 155.0.4283.62); every Windows launch carries `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--no-sandbox`;
  the **log doctor** (`backend/win_diag.rs`): a program that closes right away gets a plain explanation and, when a part fixes it, an "Install X and try again" button (once, no loop).
* `97df162`: Game Mode is left out of Safety mode (it printed "Could not connect to bus" dozens of times); WinRT programs (Microsoft's Minecraft Launcher installer) are explained: Wine cannot run them; use Java Edition (Modrinth/Prism) or Bedrock (mcpelauncher).
* **Hermes Desktop** has a native Linux build: `hermes desktop` from the CLI. The owner's WebView error came from running `Hermes-Setup.exe`.
* Tested 2026-10-18 in a hidden desktop with a throwaway data folder: `--run-windows hello.bat` ran under Proton-GE + Safety mode and wrote its file; Wine's Notepad kept running; no Game Mode lines.

### Round window buttons (`zohara-settings`, `docs/WINDOW-STYLE.md`, `6c71ac0`)
A KDE QML window decoration `kwin4_decoration_qml_zohara` (round buttons, red Close on hover, colours from the scheme), shipped to `/usr/share/kwin/decorations/`, switch in Personalization > Colors, **off by default**. Verified in the VM (light/dark, hover, maximized, on/off).
Traps: the theme name in `kwinrc` is the plain id (not `__aurorae__qml__…`); KWin keeps the QML in memory, so edits show only after sign-out (use a new id while developing); a `ButtonGroup` needs an explicit `height`. No window shadow (QML decorations cannot).

### Night light (`zohara-settings`, `docs/NIGHT-LIGHT.md`, `4423632`)
The old switch never told KWin (needs `kwriteconfig6 --notify`). Plasma 6.7 has only `Mode=DarkLight|Constant`. New group in Display: switch, "When it gets dark / All the time", warmth 2000-6000 K, live status line from KWin. Verified in the VM (screen turns orange, off restores).

### Zohara Link (`zohara-link`, `docs/FILES.md`, `docs/STREAMING.md`; Settings `docs/ZOHARA-LINK.md`)
* **Files computer → phone** (`f80aba0`, `40ae559`): `SEND_FILE`, `FILE_PUSH_*`; the phone must press Accept; folders are zipped to `~/.cache/zohara-link/outgoing/` (deleted after); several files at once with Accept all; Settings has a send-files and a send-folder button per phone.
* **Clipboard** (`40ae559`): switch "Offer copied files, folders and pictures" (off by default); copied files/folders/pictures are offered to connected phones. Text still syncs both ways. Tested with a stand-in `wl-paste` (`tests/e2e_clipboard.py`).
* **Pairing window 15 s → 60 s** (`6ef18ad`): the clock starts at connect, so typing the PIN in time over chat was impossible.
* **Stream**: the phone app rejected H.264 on Waydroid (software decoder ignored by libwebrtc), fixed with a decoder factory fallback (`fcab229`); delay changes (one-frame queue, sliced x264) and a **numbers line** on the game screen (fps, wait, decode, trip, loss, Mb/s, direct/relay; tap to hide, also `adb logcat -s ZLStream`) (`7786b37`, `6a061cb`).
  The delay the owner saw has **not been measured on the phone yet**: read the numbers first.
* Tests: `tests/e2e.py` (run with `env -u WAYLAND_DISPLAY -u DISPLAY` so the daemon does not read the real clipboard; the helper skips ADDRESSES and MEDIA_CONTROL), `tests/e2e_clipboard.py`.
