### The `zohara-stable.db` 404
pacman downloads `<repo section name>.db`. Installed systems have `[zohara-stable]`, the release only had
`zohara.db`. Every publish now also uploads `zohara-<channel>.db` (and `.files`). Checked on the live
`stable` release afterwards, and by running a real `pacman -Sy` and `pacman -Su` in the VM against it
(`-Sy` exit 0, all four repos synced). The two publish runs that followed both succeeded.

### Voice typing speed
`makepkg` exports `SOURCE_DATE_EPOCH`. With it set, whisper.cpp's ggml turns every SIMD option off by
default, so `build-avx2` (which set no flags of its own) came out byte-identical to `build-base`: same
SHA-256, zero AVX instructions. Fix: pass `-DGGML_AVX/AVX2/BMI2/FMA/F16C=ON` explicitly. These are the
same five CPU flags `zohara-settings` checks (`src/backend/dictation.rs`) before choosing that binary.

Whisper "base" q8, a 7.2 s clip, two physical cores of an i5-13420H, three runs each:

| Threads | Before | After |
|---|---|---|
| 1 | 12.9 s | 2.9 s |
| 2 | 7.7 s | 1.8 s |

Tested with the packaged build on four virtual CPUs (`qemu64`, `Nehalem`, `Haswell`, host): upgrade from
`1.9.4-1` is clean, the fast engine dies with "Illegal instruction" on CPUs without AVX2 (so the selection
in Settings is essential, and it picked correctly everywhere), and `zohara-settings --dictate` recognised
the test sentence end to end with audio played into a virtual microphone. Not tested: a real microphone,
AMD CPUs, under 4 GB of RAM. The old-CPU numbers are for restricted instructions on a fast host, not a
slow chip.

## Open items (new today, most important first)

   was in the release but missing from `zohara.db` because `zohara-voice` published 8 s later. It healed on
   the next publish. A `concurrency:` group is NOT a safe fix: GitHub cancels all but one queued run, which
   drops publishes. Better: a check after the upload that rebuilds if a package file is not in the database.
2. **Settings > Home says "Network: Not connected" while Network & internet shows the wired connection
   connected.** Probably only checks Wi-Fi. In `zohara-settings`, not investigated.

## Brave Origin, not Brave Browser

Two different products with different Arch packages: `brave-origin-bin` is Origin, `brave-bin` is Browser.
Both are official (Brave is the AUR maintainer). The ISO installs `brave-origin-bin` and Settings' web-apps
page prefers `brave-origin`. Brave Origin is free on Linux, but the first launch shows a one-time dialog:
the user must click **"Proceed with Origin for free on Linux"**. Worth one line in Welcome; not done.
Source: Brave's help article "What is Brave Origin?".

## How the work was done on Linux (no WSL)

- **ISO build:** the same Docker image as CI. Docker on Ubuntu/Zorin needs the `docker-buildx` package too
  (`docker.io` alone fails with "BuildKit is enabled but the buildx component is missing"). On a fresh
  install, `sudo systemctl daemon-reload` and `reset-failed` may be needed if `docker.socket` is stuck.
  `scripts/build-iso-linux.sh` does it in one command (builds the image with the same arguments as CI, then
  the ISO, then prints the file's timestamp and SHA-256).
- **Scripts now live in `scripts/`:** `rebuild_fast.sh` and `create_update_bundle.sh` were moved there from the
  repo root (CI and `zohara-profile/build-iso.sh` updated). The VM helpers are in `scripts/vm/` and
  `scripts/vm/guest/` (see its README).
- **The build leaves the working tree dirty:** two tracked Settings files deleted and six
  `zohara-profile/airootfs/root/*.pkg.tar.zst` untracked. Do not commit those.
- **Building a package with `makepkg` for testing** (Arch container, non-root user, `--nodeps --nocheck`)
  matches what CI does; a plain `cmake` build does NOT (no `SOURCE_DATE_EPOCH`), which is how the voice
  bug hid.
- **VM rig on a normal user:** see `scripts/vm/README.md` ("Running as a normal user").
