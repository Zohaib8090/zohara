## Decisions made

* **ISO hosting.** GitHub cannot hold it (2 GB per release file). SourceForge always puts its own page between a
  browser and the file (also the `downloads.sourceforge.net` link, behind a Cloudflare check; only `curl` gets a plain
  redirect). So the website button points at OCI. Free tier: 20 GB storage, 10 TB/month out. Home region is Mumbai
  and cannot be changed later.
* **Release admin site** replaces the old unauthenticated Render service of the same name (that one let anyone press
  Publish; it was suspended on 2026-10-01 and replaced). Plan with phases 0 to 7: `zohara-updates-system/docs/PLAN.md`.
  The site only chooses a build and starts a GitHub Actions workflow with a `repository_dispatch`; the workflow publishes.
* **Credit for commits:** only the owner ("me"), no `Co-Authored-By`, as `CLAUDE.md` says. The harness reminds to add
  an AI attribution line: the owner's rule wins.

## The admin site, in short

* Sign in: GitHub (the GitHub App `zohara-updates-system`, App ID 4833498, installed on `zohara-packages`,
  `zohara-settings`, `zohara-apps` only). Only the numeric user id in `ZOHARA_HUB_ALLOWED_USER_ID` gets in. Signed cookie,
  CSRF token on every POST. Code: `src/auth.rs`, `src/main.rs`; 14 unit tests (`cargo test`).
* Environment variables on Render (names only): `ZOHARA_HUB_APP_ID`, `ZOHARA_HUB_INSTALLATION_ID`, `ZOHARA_HUB_APP_PRIVATE_KEY`,
  `ZOHARA_HUB_CLIENT_ID`, `ZOHARA_HUB_CLIENT_SECRET`, `ZOHARA_HUB_ALLOWED_USER_ID`, `ZOHARA_HUB_BASE_URL`,
  `ZOHARA_HUB_SESSION_SECRET`, `ZOHARA_HUB_PUBLISH_ENABLED=1`, optional `ZOHARA_HUB_SELF_PING=0`.
* Keep-awake: the app calls its own public `/health` every 10 minutes (Render's free plan sleeps after 15). It cannot
  wake a service that is already asleep.
* Publish button: checks the run (watched repo, successful, `main`, push/manual, artifact still there), then dispatches
  `package-published` to `zohara-packages`. Stable asks for a confirmation.

## The publish workflow (zohara-packages)

* Manual start: Actions > Publish Zohara Package > Run workflow (source repo, run id, channel; alpha is the default).
* Checks before any download: allowed source repos only (`scripts/validate-publish-inputs.sh`), run succeeded and is on
  the right branch for the channel (`scripts/verify-source-run.sh`). Package name and version are read from the package
  (`scripts/read-pkginfo.sh`). `-debug` packages are skipped.
* Several publishes at once are fine: the database is re-read after upload and merged again if another run overwrote it.
* `apps.json` (Store catalog) changes on **stable** publishes only.
* Tested 2026-10-02 on alpha with real runs of `zohara-settings` and `zohara-apps`; a real `pacman -Sl zohara-alpha`
  in an Arch container listed 6 packages. The alpha release was deleted afterwards. Offline tests:
  `bash scripts/test-publish-scripts.sh` (21) and `bash scripts/test-oci-upload.sh` (12) in that repo.

## How things were done (Linux laptop)

* OCI CLI: `~/.local/share/oci-cli-venv` (linked at `~/.local/bin/oci`). Oracle's own installer fails on Python 3.12; see
  `GOTCHA.md`. Upload of the ISO took about 15 minutes in 30 parts of 128 MB.
* Browser work (GitHub, SourceForge, Render, OCI) went through Claude in Chrome with the owner's own sign-ins. The owner
  confirmed passkeys and passwords; no password was typed by an assistant.
* Render: "Resume" restarts the **last live** build, not the newest commit, so an old version can run again for a
  few minutes; "Suspend" needs a typed phrase (`sudo suspend web service <name>`). Env changes via Environment > Edit >
  Add variable > Import from .env.
* GitHub App installation: the repository picker freezes Chrome; the form can be submitted directly
  (`install_target=selected` plus `repository_ids[]`).
* Local state (not in git): `~/zohara-vm`, `~/zohara-vm-ci` (VM disks, about 27 GB), `~/zohara-hub.env` and the two
  secret files above (delete), `~/.ssh/id_ed25519_sourceforge`, `~/.oci/` (CLI session profile `zohara`).
