Zohara's Arch packages are frozen at **2026/09/26** (`approved_date` in `zohara-pipeline/manifest.json`, unchanged since 2026-10-05). This compares Arch's own repository snapshots (archive.archlinux.org: 2026/09/26, 2026/10/14, 2026/10/20) for the **1393 packages installed on the owner's laptop** (it matches the 09/26 snapshot exactly: 0 differences).

* 09/26 -> **10/14** (the last day before Plasma 6.8): **417 installed packages changed, about 2.1 GB to download.**
* 10/14 -> 10/20: another **131** (Plasma 6.8.0 arrived on 10/15, which removes the X11 session: see `PACKAGE-LIST-2026-10-21.md`).
* Arch's security tracker (`security.archlinux.org`) gave **no usable list**: its newest entry is old and it does not track `linux-zen`, so no CVE list is claimed here. The security-relevant items below are judged by package, not by advisory.

## What to prepare before moving the date (recommended target: **2026/10/14**, not later)
1. **Why 10/14:** it brings the 25 days of fixes and keeps Plasma 6.7.5 with `kwin-x11`, so the X11 session still works. Any later date brings Plasma 6.8.0 (no X11).
2. **Test the real update path in the VM**: install the current ISO (09/26), then point its `/etc/pacman.d/mirrorlist` at 2026/10/14 and run the update (this is what machines do after you approve). Check it finishes, boots, signs in on **both Wayland and X11**, and the btrfs snapshot (snap-pac) is made before it, so a roll-back exists.
3. **Re-run the feature tests on 10/14** (Qt 6.12, libadwaita 1.10): Settings and Store open and every page loads; cube effect, live wallpaper, dynamic desktops, the `zohara` window decoration and round buttons, night light; Display page (kscreen); Wine and a Windows `.bat`; archive install; Hibernate (new kernel); zram on, networkd still masked.
4. **Packages not from Arch** that were built for Qt 6.11: `latte-dock-ng` (chaotic-aur; check it has a Qt 6.12 rebuild at that date, else it must be dropped or rebuilt), our own `zohara-terminal`, `zohara-voice`, `zohara-snapshots` (rebuild in CI and test), the AUR/chaotic apps (Brave, Chrome, VS Code, Claude: not Qt, expected fine).
5. **NVIDIA**: confirm `nvidia-open-dkms` 615.78 builds against `linux-zen` 7.2.9 headers (the ISO has `linux-zen-headers`).
6. **CI builds**: Zohara's own packages are built in an Arch container at *today's* Arch. A package built against newer libraries can fail on a machine still frozen at 09/26. Check what the CI container's Arch date is, and pin it to the approved date.
7. **Then you approve the date** (`tools/approve.sh 2026/10/14` in the container with your minisign key; the date must not be older than the one an ISO pinned). Warn before publishing: this changes every machine on its next Update. A new ISO at that date is a separate step.
8. **Before 6.8 (later)**: decide the X11 answer (see the chat notes: Plasma 6.7 until early 2027, then Wayland, optional Xfce); remove `kwin-x11` only then.
